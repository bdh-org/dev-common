# fleet-consumers.txt — the expected list of repos that carry submodule pins.
#
# ONE list, read by BOTH halves of the pin loop (home-infra#362), which since
# home-infra#368 live in two repos:
#
#   dev-common   scripts/bump-submodule-pins.sh          remediation — open a PR that
#                (this repo, beside this file)                         moves the pin forward
#   home-infra   scripts/audit-submodule-pins.sh         detection   — how far behind is
#                reads it as common/scripts/fleet-consumers.txt        every pin?
#
# The halves are split because the remediation runs in CI and the detection is run by a
# human: a reusable workflow can only reach code in a repo its callers can see, and
# home-infra is private. Home-infra keeps ONE copy of this list all the same — its own
# `common/` submodule IS this directory, so the audit reads this very file rather than a
# copy of it, and there is nothing to drift.
#
# It lives in a data file, rather than inside either script, because two lists would
# drift and the drift would be invisible: the audit would report a repo the bump never
# sweeps, or the bump would open PRs against a repo nobody audits. The absence each one
# detects is only visible to something holding the expected list, so there has to be
# exactly one of it.
#
# It is a list of STACK MEMBERS, which is knowledge dev-common otherwise does not carry --
# it is the dev tooling every project across every stack pins, and it names no stack's
# repos anywhere else. That is a real cost and it was paid deliberately (home-infra#368):
# the alternative is two expected lists, and an expected list that drifts detects nothing.
# Nothing in dev-common's own tooling reads this file; only the two scripts above do.
#
# FORMAT — one consumer per line:
#
#   <org>/<repo> | <max-behind or -> | <max-days or -> | why this repo's pins matter
#
# Fields 2 and 3 are per-repo overrides for the AUDIT's thresholds; `-` takes the
# global default (MAX_BEHIND=10 commits, MAX_DAYS=30 days). The bump ignores them:
# "current" is the only target it has. Blank lines and `#` comments are skipped.
#
# The registry names the CONSUMERS, not the pins. Submodules are discovered from each
# repo's own .gitmodules on its default branch, so a repo GAINING a submodule is picked
# up automatically while a repo VANISHING from the fleet is a line that stops matching
# (which the audit reports as stale registry, not as a pass).
#
# Not listed, on purpose: dev-common and dataflow declare no submodules (a line here
# would fail as stale); brief, roy and devtemplate consume dev-common but are not stack
# members. Adding any of them is one line.
#
# Apostrophes are SAFE here. They were not when this block lived inside the audit as
# the default word of a "${CONSUMERS:-...}" expansion, where bash parses quotes even
# inside the double-quoted expansion — one `repo's` and the script did not parse at
# all. Moving the data into a file retired that trap along with the duplication.
